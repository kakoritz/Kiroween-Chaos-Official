# Sample hardening spec (TV3-C11, C12, C13)

Generated by the pattern miner and spec writer from a real run, not typed by hand. The run id in the files is shown as `<run>`; the real folder name was `.kiro/specs/hardening-<run>/`.

## How it was made

1. `npm run build:bots`, then `HAUNT_PORT=7081 HAUNT_PROVIDER_PORT=7082 npm run demo -- --no-open` (the live server with real bots).
2. `npm run haunt -- improve --url http://127.0.0.1:7081 --seed 7 --speed 4 --pace show --rounds '[{"lanes":5,"orders":5,"intensity":5},{"lanes":4,"orders":5,"intensity":5}]'`: run the tournament, mine, apply the cheap patterns as policy overlay, write the spec for the rest, rerun the same plan and seed, compare.
3. `npm run haunt -- spec-lint .kiro/specs/hardening-<run>` answered `spec-lint ok (5 requirements)`.

## Files

- `requirements.md`, `design.md`, `tasks.md`, `README.md`: the spec (EARS requirement with evidence, impact and hypothesis; the smallest patch with a diff budget, risk and rollback; tasks with a regression test and an acceptance line; sorted by downtime cost).
- `improve-report.txt`: what the loop printed. **Closed 0 of 5 patterns, grade C before and after.** That is the honest result of this run: the tournament plan (seeded storm) hits the same stages again and the Retrier-class lanes already had the backoff lesson, so the overlay did not remove `payment + http_404 + order_lost`, which the Rookie also meets and which needs the code change in the spec. A pattern is marked verified only when the rerun shows it gone, so none was.
- `patterns.json`: the pattern store after the run (evidence trimmed).

Nothing in this folder was applied to code. Kiro applies a spec with the review step.
