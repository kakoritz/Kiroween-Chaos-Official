# Contract v1.2 (additive, `contractMinor: 2`)

Adds to `PROTOCOL.md`, `CONTRACT.md` and `V1_1.md`. `contractVersion` stays 1. Rules continue at 48. Source: `.kiro/specs/tournament-v3/spec.md`. Contract-label PR; Lane B approves.

## 1. Stage list is data
`state` and `hello` carry `app.stages`: `[{id, label, kind: "effect"|"read"|"poll"|"final", icon?}]`. The UI draws chips from this list.
- `orders` (v2 order): `account, create, submit, payment, confirmation, receive, process, updates, ship, transit, handoff`.
- Legacy runs (`intake, account, ...`) keep working: if `app.stages` is missing the UI uses the legacy list (rule 48).
- `stage` in events is one of `app.stages[].id`.

## 2. Rounds and the review state
- Events: `round_start {round, total, lanes[], orders, intensity, seed}`, `round_end {round, standings[{lane, rp, rank, eliminated?}], eliminated?, awards?, lessons[], cases[]}`, `awaiting_next {round}`, `tournament_end {champion, awards[], casebookRef}`.
- `POST /api/next` resumes after `awaiting_next`; `GET /api/tournament` returns rounds, standings, corpses, awards, casebook.
- Rule 49: after `round_end` or `wave_end` in a tournament or campaign the server emits `awaiting_next` and starts no orders until `POST /api/next` (or an explicit `autoContinueSec` setting).
- Rule 50: eliminated lanes emit no further order events but remain in `state.lanes[].fallen = {round, stage, cause}`.

## 3. Corpses and elimination
- `lane_eliminated {lane, round, stage, cause, epitaph}` and `corpse {lane, stage, kind: "eliminated"|"wall", round, epitaph}`.
- Rule 51: `state.corpses[]` lists all corpses so a late joiner sees them.

## 4. Faults and creatures added
Faults at stage `transit`: `weather`, `road_hazard`, `delay`, `out_of_gas`, `not_on_truck` (`wrong_address` exists). Creature names for UI art: `storm_crow` (weather), `pothole_imp` (road hazard), `fuel_wraith` (out of gas), `lost_parcel_ghoul` (not on truck); `delay` reuses `scarecrow`. Fault `gremlin` (floor rule) with creature `gremlin`; `unknown` faults carry `unknown: true` and a generated `fingerprint`.
- Rule 52: `chaos` events set `unknown: true` for fuzz faults and `source: "plan"|"gremlin"|"curse"|"fuzz"`.

## 5. Intensity, curses, learning, cases, patterns
- `intensity {level: 1..11, source: "player"|"ramp"|"plan"}`; `POST /api/intensity {level}`.
- `curse_start {lane, id, kind: "404"|"slow"|"flaky500"|"clock_skew"|"rate_limit", endpoint, rate?}`, `curse_end {lane, id}`, `curse_response {lane, order, stage, curse, class: "handled"|"reported"|"swallowed"|"crashed"}`.
- `outage {lane, stage, outageMs, seed}` on random outage start (range by level, 1 to 30 s at 1x).
- `lesson {lane, signature, mechanism, round, via: "overcame"|"suggested"}`.
- `case {signature, lane, round, order, outcome: "solved"|"partly"|"lost", mechanism?, costMs, costPoints, unknown?}`.
- `pattern {id, signature, count, downtimeMsTotal, status}`; `spec_written {runId, path, patterns[]}`.
- Rule 53: every `chaos` start has exactly one end: a later `stage_done`, `order_done` or `order_failed` for that order (the UI uses this to dissipate swarms).
- Rule 54: `issuesTotal >= 1` per lane per `round_end` (floor rule); `round_end.standings[].issues` is included so a client can verify.
- Rule 55: score `reason` values added: `lesson bonus`, `swallowed`, `elimination` (display only, delta 0).

## 6. Endpoints added
`GET /api/tournament`, `POST /api/next`, `POST /api/intensity`, `POST /api/curse {lane, kind, endpoint}`, `GET /api/casebook`, `GET /api/patterns`, `GET /api/lessons/:lane`, `DELETE /api/lessons` (reset).
